# SEO Automation Report — 2026-09-23

## Shipped today

**Phase 1: Core Web Vitals audit of the hero/spotlight gradient-glow CSS** — no site code changed; PLAN.md + this report are the only files touched today.

Task: "check the animated gradient/glow CSS isn't hurting LCP/CLS on mobile."

Method: installed Playwright + the sandbox's pre-installed headless Chromium (`/opt/pw-browsers/chromium-1194`), served the repo with `python3 -m http.server`, and ran a real headless-browser pass against all 7 live pages at a 375×812 mobile viewport with 4x CPU throttling (to simulate a mid-tier phone), using `PerformanceObserver` for `layout-shift` and `largest-contentful-paint` entries (the same signals Chrome/Lighthouse use for CLS/LCP).

Findings:
- **No animation exists.** Grepped the whole codebase for `@keyframes`, `animation`, `requestAnimationFrame`, `<canvas>`, `setInterval` — none found anywhere. The "glow" is a single static `radial-gradient` background, painted once via an absolutely-positioned `::before` pseudo-element (`z-index: -1`, taken out of normal document flow via `position: absolute`). There's no continuous repaint/GPU cost to worry about.
- **CLS = 0** on all 7 pages. Makes sense given the above — the glow element is out-of-flow and never resizes, so it can't shift layout.
- **LCP = 428–768ms** across all 7 pages, even under 4x CPU throttle — well inside Google's "good" (≤2.5s) threshold, most with large margin. The LCP element on every page was the hero `<p class="lede">` text, not the gradient — confirming the gradient isn't blocking or delaying the actual largest paint.

Per-page numbers (CLS / LCP ms / LCP element):
| Page | CLS | LCP (ms) | LCP element |
|---|---|---|---|
| `index.html` | 0 | 768 | `p.lede` |
| `case-studies/index.html` | 0 | 468 | `p.lede` |
| `case-studies/automation.html` | 0 | 536 | `p.lede` |
| `case-studies/contract-to-hire.html` | 0 | 428 | `p.lede` |
| `case-studies/real-money-gaming.html` | 0 | 476 | `p.lede` |
| `contract-to-hire/index.html` | 0 | 452 | `p.lede` |
| `release-readiness/index.html` | 0 | 448 | `p.lede` |

**Conclusion: the task's premise doesn't hold — the gradient/glow isn't animated and isn't hurting LCP or CLS.** No code change was needed, so nothing was pushed to `main` for the site itself. Checked the task off in PLAN.md with this finding; PLAN.md + this report get pushed straight to `main` per the runbook's documentation-only step (no browser-verification pass needed for that push — just confirmed the markdown is well-formed).
