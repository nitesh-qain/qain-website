| Page | CLS | LCP (ms) | LCP element | Horizontal overflow |
|---|---|---|---|---|
| `index.html` | 0 | 948 | `p.lede` | none |
| `blog/index.html` | 0 | 284 | `h1` | none |

CLS = 0 on every page. LCP ranges 284–948ms — even the heaviest page (`index.html`, with ~368KB of images) is comfortably inside Google's "good" ≤2.5s threshold with large margin, even under 4x CPU throttle. No horizontal overflow on any page at 375px (`scrollWidth === viewportWidth` throughout). Console showed only the known pre-existing sandbox-proxy block on `googletagmanager.com` (`ERR_TUNNEL_CONNECTION_FAILED`), confirmed present on every page before today's audit too and unrelated to Core Web Vitals.

**Conclusion: no regressions since the 2026-09-23 baseline audit, and no code change needed.** Closed the task as verified-clean, same outcome as the original audit. Images on the heaviest page already carry explicit `width`/`height` and `loading="lazy"` below the fold from the 2026-11-05 image/asset audit, which is almost certainly why `index.html`'s LCP stays low despite the extra weight.
